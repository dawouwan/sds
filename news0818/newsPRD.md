## 1. 개요

### 1.1 한 줄 정의

키워드를 넣으면 네이버 뉴스에 색인된 기사를 **송고 시각 순 또는 검색 순위 순**으로 훑어보고, 원문으로 바로 넘어가는 개인용 웹 검색 도구.

### 1.2 만드는 이유

네이버 뉴스 검색 결과 화면은 광고·연관 검색어·섹션 추천이 섞여 있어서 "이 키워드로 오늘 뭐가 들어왔나"만 빠르게 확인하기가 어렵다. 그 한 가지 동작만 남기고 나머지를 전부 걷어낸다.

### 1.3 비목표 (Non-goals)

명시적으로 **하지 않는** 것들. 나중에 논의가 다시 올라오면 이 항목을 먼저 볼 것.

| 안 하는 것 | 이유 |
|---|---|
| 로그인 · 계정 | 개인 사용. 서버에 저장할 사용자 상태가 없음 |
| 서버 DB | 검색 결과는 휘발성. 저장할 이유가 생기면 그때 재논의 |
| 기사 본문 크롤링 · 요약 | 저작권 문제. 항상 원문으로 보낸다 |
| 스토어/도메인 배포 | 로컬 `npm run dev` 로 충분 |
| 뉴스 외 검색(블로그·카페·쇼핑) | API 는 같지만 화면 문법이 다름. 별도 프로젝트 |
| 실시간 급상승 검색어 | 네이버가 API 를 제공하지 않음 (§7.4) |

## 2. 사용자와 사용 맥락

- **사용자:** 나 혼자.
- **전형적 세션:** 30초 ~ 2분. 키워드 하나 → 목록 스캔 → 원문 1~3건을 새 탭으로 열기 → 이탈.
- **주 사용 기기:** 데스크톱 브라우저. 모바일은 보조지만 레이아웃이 깨지면 안 됨.
- **재방문 패턴:** 같은 키워드를 며칠에 걸쳐 반복 검색. → 주소창 파라미터로 재현 가능해야 함 (§5.1 R-6).

## 4. 디자인 콘셉트

### 4.1 콘셉트: 통신사 수신기

기사를 "카드"로 보지 않는다. **레일에 순서대로 걸린 전문(電文)** 으로 본다.
목록 왼쪽에 세로 레일이 하나 흐르고, 기사마다 점(tick)이 걸린다.

### 4.2 시그니처: 정렬에 반응하는 레일

**레일이 재는 값이 정렬 기준에 따라 바뀐다.** 정렬이 토글 버튼의 상태로만 존재하지 않고 목록 구조 자체를 바꾼다.

| | 최신순 (`date`) | 정확도순 (`sim`) |
|---|---|---|
| 레일 선 | 실선 — 시간축 | 점선 — 순위축 |
| 스탬프 | `14:22` (송고 시각) | `001` (전체 순위) |
| tick 모양 | 원 | 사각 |
| 날짜 구분선 | 있음 (`오늘 · 08.18 화`) | 없음 |
| 안내 라벨 | `레일 = 송고 시각` | `레일 = 검색 순위` |

> 순번 표기(`001`)는 정확도순에서만 쓴다. 최신순에서 순번은 아무 정보도 담지 않으므로 넣지 않는다.

### 4.3 디자인 토큰

**색 — 차가운 청회색 필드에 신호등 오렌지 한 점**

| 토큰 | Light | Dark | 역할 |
|---|---|---|---|
| `--field` | `#E8EEF4` | `#0B131D` | 페이지 바닥 |
| `--card` | `#FFFFFF` | `#131E2B` | 입력·패널 표면 |
| `--ink` | `#0F1B2A` | `#E6EEF6` | 제목·주요 텍스트 |
| `--ink-2` | `#4E6377` | `#97AABB` | 본문 요약 |
| `--ink-3` | `#8397A9` | `#677D90` | 메타·스탬프 |
| `--rule` | `#CBD9E4` | `#24333F` | 레일·구분선 |
| `--signal` | `#D8501A` | `#FF7C42` | 강조어, hover, 램프 |
| `--sky` | `#BFDCEF` | `#2A4A66` | 검색어 하이라이트 배경, 포커스 링 |

액센트는 **오렌지 한 색만** 쓴다. 다른 색을 추가하려면 이 항목을 고칠 것.

**타이포 — IBM Plex 슈퍼패밀리**

| 역할 | 서체 | 사양 |
|---|---|---|
| 본문·제목 | IBM Plex Sans KR | 400 / 500 / 600 |
| 시각·순위·건수·코드 | IBM Plex Mono | 400 / 500 / 600, `tabular-nums` |

- 기사 제목 `17px / 1.45 / 600 / ls -0.02em`
- 요약 `14px / 1.65 / 400`, 2줄 클램프
- 메타 · 스탬프 `11.5~12px mono`

**모션**

| 대상 | 동작 |
|---|---|
| 레일 | `scaleY(0→1)`, 500ms — 결과 도착 시 위에서 아래로 그어짐 |
| 기사 행 | `translateY(7px)` + fade, 360ms, **22ms stagger** (최대 14번째까지) |
| hover | tick 이 signal 색으로 채워지고 1.25배, 스탬프가 `--ink` 로 진해짐 |

`prefers-reduced-motion: reduce` 에서 전부 무효화.

| R-7 | 늦게 도착한 이전 요청이 최신 결과를 덮어쓰지 않을 것 (요청 티켓 방식) |

| ID | 요구사항 |

### 5.3 F-3 정렬

| ID | 요구사항 |
|---|---|
| R-12 | `최신순`(`sort=date`) / `정확도순`(`sort=sim`) 2택. 기본값 **최신순** |
| R-13 | 정렬 변경 = `start=1` 부터 **재검색**. 클라이언트 재정렬 아님 |
| R-14 | 검색어가 없거나 로딩 중이면 비활성 |

각 항목이 담는 것:

| 필드 | 출처 | 표시 |
|---|---|---|
| 제목 | `title` | 17px, `<b>` 강조 유지, 클릭 시 새 탭 |
| 요약 | `description` | 2줄 클램프, `<b>` 강조 유지 |

### 5.6 F-6 화면 상태

| 상태 | 진입 조건 | 화면 |
|---|---|---|
| `idle` | 최초 진입, `?q=` 없음 | 큰 헤드라인 + 검색창 + 키워드 칩 |
| `loading` | 검색 제출 | 레일 + 스켈레톤 6행 (실제 목록과 동일한 그리드) |
| `ready` | `items.length > 0` | 결과 목록 |
| `empty` | `items.length === 0` | 수신 0건 패널 + 대안 키워드 칩 |
| `error` | `ok: false` | 오류 코드 패널 + 재시도 |

**카피 원칙**

- 사과하지 않는다. 무슨 일이 있었고 무엇을 하면 되는지만 쓴다.
- 빈 화면은 행동 유도로 끝낸다 — 결과 없음 화면은 반드시 클릭 가능한 대안 키워드를 제시한다.
- 오류 패널은 상단에 코드(`QUOTA_EXCEEDED`)를 mono 태그로 노출. 디버깅용.

## 7. 데이터 계약

### 7.1 내부 API

```
GET /api/news?query=&sort=&start=&display=
```

| 파라미터 | 값 | 기본 | 검증 |
|---|---|---|---|
| `query` | 문자열 | — | 필수, trim 후 1~80자 |
| `sort` | `date` \| `sim` | `sim` | 그 외 값은 `sim` 으로 폴백 |
| `start` | 1~1000 | 1 | 1000 초과 시 `RANGE_EXCEEDED` |
| `display` | 1~100 | 20 | 범위 밖은 클램프 |

**성공 응답**

```ts
{
  ok: true,
  items: NewsItem[],
  total: number,        // 네이버가 보고한 전체 건수
  reachable: number,    // min(total, 1000) — 실제로 받을 수 있는 수
  start, display,
  nextStart: number | null,
  sort, query
}
```

`NewsItem`: `id` / `rank` / `titleHtml` / `descriptionHtml` / `titleText` / `press` / `link` / `originallink` / `publishedAt(ISO)`

### 7.2 서버 캐시

동일 `sort|display|start|query` 조합에 대해 **60초 메모리 캐시**, 최대 150 엔트리 LRU.
연타·정렬 왕복으로 일일 한도를 태우지 않기 위함. 프로세스 재시작 시 소멸 — 그걸로 충분하다.

### 7.3 `<b>` 태그 처리

네이버는 제목·요약에 검색어를 `<b>` 로 감싸서 주고, 나머지 문자는 HTML 엔티티로 이스케이프해서 준다.

서버 처리 순서:
1. `<b>` / `</b>` 토큰 기준으로 분할
2. 태그가 아닌 조각 → 엔티티 디코드 → **재이스케이프** (`&` 는 마지막에 디코드)
3. `<b>` 만 되붙여서 반환

→ 클라이언트의 `dangerouslySetInnerHTML` 은 `<b>` 외 어떤 태그도 받을 수 없다.

### 7.4 네이버 API 제약

| 제약 | 영향 |
|---|---|
| `start` 최대 1000 | 전체 건수와 무관하게 1,000건이 상한. UI 에 명시 (R-20) |
| `display` 최대 100 | 문제 없음 (20 사용) |
| 기간 필터 파라미터 없음 | 날짜 범위 검색 불가. 클라이언트 후처리만 가능 → P2 후보 |
| 매체 필터 파라미터 없음 | 위와 동일 → P2 후보 |
| 실시간 검색어 API 없음 | 인기 키워드는 하드코딩 (R-11) |
| CORS 미허용 | 브라우저 직접 호출 불가 → 서버 프록시가 필수 (S-2 와 이해관계 일치) |
| 하루 25,000건 | 캐시로 완화 |

## 8. 오류 코드

| 코드 | HTTP | 원인 | 재시도 버튼 |
|---|---|---|---|
| `NO_CREDENTIALS` | 500 | `.env.local` 미설정 | 없음 |
| `BAD_CREDENTIALS` | 502 | 네이버가 401/403 반환 | 없음 |
| `EMPTY_QUERY` | 400 | 검색어 없음 | — |
| `QUERY_TOO_LONG` | 400 | 80자 초과 | — |
| `RANGE_EXCEEDED` | 400 | `start > 1000` | — |
| `QUOTA_EXCEEDED` | 502 | 일일 한도 초과 | 있음 |
| `UPSTREAM_ERROR` | 502 | 그 외 네이버 오류 | 있음 |
| `NETWORK_ERROR` | 504 | 타임아웃(8초)·연결 실패 | 있음 |

키 문제(`NO_CREDENTIALS`, `BAD_CREDENTIALS`)는 재시도해 봐야 같은 결과이므로 버튼을 숨기고 조치 방법만 안내한다.

## 9. 기술 스택

| 항목 | 선택 | 근거 |
|---|---|---|
| 프레임워크 | Next.js 15 App Router | 라우트 핸들러 = 키를 숨길 서버 경계. 별도 백엔드 불필요 |
| 언어 | TypeScript strict | API 응답 형태를 타입으로 고정 |
| 스타일 | 순수 CSS + 커스텀 프로퍼티 | 의존성 0. 다크모드를 변수 재정의 한 블록으로 처리 |
| 상태 관리 | `useState` | 전역 상태가 없다 |
| 폰트 | Google Fonts `<link>` | `next/font` 빌드타임 페치 의존 회피 |

**Tailwind 미채택:** 레일 그리드·의사요소 기반 연속선이 유틸리티 클래스로는 오히려 길어진다. 토큰이 8개뿐이라 CSS 변수로 충분.

## 11. 접근성 기준

- 모든 인터랙티브 요소에 `:focus-visible` 아웃라인 (`--signal`, offset 2px).
- 정렬 = `role="group"` + `aria-pressed`. 칩도 `aria-pressed`.
- 로딩 = `role="status"` + `aria-busy`, 오류 = `role="alert"`.
- 결과 건수 문장에 `aria-live="polite"`.
- 레일 스탬프의 압축 표기(`14:22`, `001`)는 `title` 속성으로 전체 의미 제공. 메타 줄에는 항상 전체 날짜를 둔다.
- 640px 이하에서 레일 폭 `76px → 56px`, 헤드라인·키캡 축소.

## 12. 결정 기록

| 결정 | 대안 | 채택 이유 |
|---|---|---|
| 서버 라우트 프록시 | 클라이언트 직접 호출 | 네이버가 CORS 를 막아서 애초에 불가능. 동시에 S-1 도 자동 충족 |
| 기본 정렬 = 최신순 | 정확도순(API 기본) | "오늘 뭐가 들어왔나"가 주 용도 |
| 정렬 변경 시 재검색 | 받아온 목록 클라이언트 재정렬 | 20건만 재정렬하면 전체 순서가 아님. 거짓 정보가 됨 |
| `더 보기` 버튼 | 무한 스크롤 | 스크롤 도중 의도치 않게 호출량이 늘어남. 1,000건 상한도 명시하기 어려움 |
| 순번은 정확도순에서만 | 항상 `01/02/03` | 최신순의 순번은 아무 정보도 없다 |
| 서버에서 `<b>` 화이트리스트 | 클라이언트 sanitize 라이브러리 | 의존성 없이 처리 가능. 신뢰 경계를 서버에 둠 |
| 인기 키워드 하드코딩 | 스크래핑 | 네이버 실시간 검색어는 서비스 자체가 폐지됨 |
| CSS 변수 다크모드 | 토글 버튼 + 저장 | OS 설정을 따르는 게 맞다. 저장할 상태를 만들지 않음 |

## 13. 로드맵

**P1 — 검색 히스토리**
최근 검색어 10건을 `localStorage` 에 저장, idle 화면에서 칩 위에 노출. 삭제 가능.
*조건: 하드코딩 칩보다 실제로 더 자주 쓰게 되는지 2주 관찰 후 착수.*

**P2 — 매체 · 기간 필터**
네이버가 파라미터를 주지 않으므로 **받아온 결과 안에서만** 거르는 클라이언트 필터.
"전체 12,345건 중 필터링"이 아니라 "표시된 N건 중 필터링"임을 UI 에 명확히 쓸 것. 이걸 흐리면 거짓말이 된다.

**P3 — 키워드 비교 뷰**
두 키워드를 나란히 놓고 레일 두 줄로 시간축을 맞춰 보기. 시그니처(§4.2)의 자연스러운 확장.

**P4 — 읽음 표시**
방문한 링크를 `localStorage` 로 기억해 스탬프를 흐리게. 같은 키워드 반복 검색 시 새 기사만 눈에 들어오게 하는 것이 목적.
